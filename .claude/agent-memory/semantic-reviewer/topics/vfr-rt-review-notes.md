## Phase B Server Actions (commit 0dedd3c4, 2026-06-19)

- **`_error-messages.ts` RPC-raise map is intentionally partial**: only 3 of 5 RAISE tokens are mapped; `user_not_found_or_inactive` and `active_session_exists` fall through to the generic `'Failed to start exam'` fallback. The `active_session_exists` path is effectively unreachable in normal operation (unique-violation concurrent-start race). The `user_not_found_or_inactive` token is reachable (soft-deleted student with live JWT). Both are ISSUE severity per §5 sanitize — the file's own comment says "keep in sync with the RPC body".
- **`submitVfrRtExam` drops the `expired` flag from the RPC response**: the RPC returns `expired: true` on timer-expiry (a non-error success path). The Server Action discards `data` entirely and returns only `{ success: true, session_id, redirect_to }`. Phase C UI cannot distinguish a timed-out submission from a normal one without a separate DB read. Flag ISSUE on this commit; watch for Phase C UI.
- **`normalize-answer.ts` TS/SQL parity confirmed**: character-for-character same 12-char punct set, same operation order. TS regex `/[\][.,;:!?"'()]/g` strips both `[` and `]` — confirmed by Node execution. Do NOT re-flag parity issues on this normalizer.

## dialog_fill delimiter guard — mig 125 (#951, commit d90254d2)

- **`dialog_fill_blanks_delimiter_free(p_blanks)` is now a TOTAL function** (mig 125): BOTH set-returning calls — outer `jsonb_array_elements(p_blanks)` and inner `jsonb_array_elements_text(e->'synonyms')` — wrap their arg in `CASE WHEN jsonb_typeof(...)='array' THEN ... ELSE '[]'::jsonb END`. Never raises 22023 on any jsonb input (array/scalar/object/JSON-null/SQL-NULL). Do NOT flag the bare SRF calls as "raises on non-array" — the CASE guard precedes them.
- **The delimiter helper / constraint (1) `questions_dialog_fill_blanks_delimiter_free` is authoring-hygiene only, NOT a student-leak path.** The student-leak guard is constraint (2) `questions_dialog_fill_template_wellformed` on `dialog_template` (mig 125 L92-96), independent of `blanks_config` typing. `blanks_safe` (mig 118/126) emits `{index}` only — no canonical/synonym. Do NOT escalate a relaxation of the delimiter helper to a leak CRITICAL.
- **`'null'::jsonb` blanks_config edge (do-not-re-flag as ISSUE):** mig 125's total-function patch lets a dialog_fill row with `blanks_config='null'::jsonb` pass BOTH CHECKs (mig 094 `jsonb_array_length('null'::jsonb)` returns SQL NULL → CHECK `FALSE OR FALSE OR NULL` = passes; mig 125 helper returns `t`). Pre-patch the old `coalesce(...)` helper would have raised 22023 and rejected it. This is a harmless relaxation: not reachable (NOT NULL DEFAULT `'[]'`, no authoring path inserts JSON-null), not a leak, and `blanks_safe`'s own unguarded `jsonb_array_elements` would raise 22023 at read time if ever reached. Header comment (L56) says the mig-094 CHECK rejects "a non-array blanks_config" — imprecise for the `'null'::jsonb` sub-case (SUGGESTION only, not ISSUE).

No author-chosen field survives, so no assignment of ids can encode the zone→label pairing. `assertDiagramConfig` re-derives and rejects any hand-written id.
- **Bundle claim MEASURED, not inferred** (against the existing `apps/web/.next` build — note that build PREDATES the squash commit `b28cc604` but POSTDATES the branch content that introduced the ids, which is why they are present; containing `z1a077e7d6` does NOT prove it postdates the commit, so re-measure after a rebuild before restating this): all 9 zone ids ARE in a client chunk (minified as `rt("z1a077e7d6",ro)` — cite the minified call, not the source-level `box(...)` helper, and never the content-hashed chunk filename); NO label id and NO label text appears in `.next/static`; the content JSON pools are absent from the build entirely. So the layout module's own SECURITY comment is accurate. #1218 (server-only boundary) is the tracked follow-up; the two prose guards it names have no mechanical enforcement.
- **MC options ARE shuffled on both delivery paths** — `get_quiz_questions` (mig `20260702000300`) and `get_vfr_rt_exam_questions` (mig `20260623000600`), `ORDER BY random()`.
